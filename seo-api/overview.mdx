SEO reports require the location's `airbyte` plan feature. Landing-page reports also require `data_api`. An `mcp_` key needs `seo:read`, plus `sessions:read` and `events:read` for landing pages. Reports are unavailable for HIPAA locations. Call from your server, not from browser JavaScript.

## Connect Search Console

Use the [Airbyte OAuth flow](/airbyte-api/overview#connecting-with-oauth) with a Mythic-managed BigQuery destination. For OAuth initiation, send the client ID, `platform: "google_search_console"`, your registered `return_url`, and:

```json
{
  "source_config": {
    "site_urls": ["sc-domain:example.com"],
    "start_date": "2026-09-01"
  }
}
```

Use exactly one property as registered with Google. `site_urls` can be that string or a single-item array. A URL-prefix property includes the protocol and trailing slash, for example `https://www.example.com/`. `start_date` is required. The Google account must have access to the property. OAuth requests `https://www.googleapis.com/auth/webmasters.readonly`. Omit `streams` and cadence fields. Search Console must use a Mythic-managed destination and an enabled client pipeline with Tinybird copy. Data appears only after a successful **pipeline run and Tinybird copy**, not immediately after consent or a standalone Airbyte sync.

To change properties or renew consent, pass the current connection UUID as `replace_connection_id` in the same OAuth initiate request. It is supported only for Search Console. Abandoning consent leaves the old connection active. After the new connection is created, Mythic switches the pipeline to it and removes the old connection. The new reports stay in `syncing` until their first successful copy. If cleanup fails, the callback still reports success and appends `mythic_warning_code=disconnect_failed` and `mythic_replaced_connection_id` to the return URL. Retry DELETE using that old ID.

## Reports

All routes are `GET` under `/client/v1/seo`. MCP returns the same report fields plus `location_id`.

| Route | MCP tool | Report |
| --- | --- | --- |
| `/status` | `get_search_console_connection` | Property and copy readiness |
| `/overview` | `get_seo_overview` | One metrics object per period |
| `/trend` | `get_seo_trend` | Metrics by Pacific calendar day |
| `/queries` | `get_seo_queries` | Search queries ranked in the current period |
| `/pages` | `get_seo_pages` | Search Console page URLs ranked in the current period |
| `/landing-pages` | `get_seo_landing_pages` | Ranked pages plus on-site sessions, conversions and Core Web Vitals |
| `/breakdown` | `get_seo_breakdown` | Device or country rows |
| `/brand` | `get_seo_brand_split` | Branded, non-branded and anonymized search |

### Parameters

- `from`, `to`: inclusive ISO dates in Google's Pacific calendar. The maximum range is 366 days. Alternatively pass `days` and optionally `to`. Default: 28 days ending three days before today. Explicit dates can include more recent days, which may have no finalized rows yet.
- `compare=true`: return the immediately preceding equal-length range. Trend dates align by day offset. Ranked reports keep only rows observed in the current period and sort and limit those rows before attaching comparisons.
- `query_contains`, `page_contains`: case-insensitive literal substring filters, up to 200 characters. `country`: three-letter Search Console country code, e.g. `usa`. `device`: `desktop`, `mobile`, or `tablet`. Country and device are case-insensitive over HTTP.
- `/queries` accepts `page_equals`, the exact Search Console page URL. `/pages` accepts `query_equals`, the exact search query. Both are case-sensitive and combine with other filters.
- Ranked reports (`/queries`, `/pages`, `/landing-pages`, `/breakdown`): `sort` is `clicks` (default), `impressions`, `ctr`, or `position`. Position sorts ascending, the others descending. Nulls sort last. `limit`: 1–1000, default 100. `offset`: rows to skip, default 0. JSON includes `total_rows` (before pagination) and `next_offset` (null at the end or past it). Ready reports also include a `publication` token. Send it with `next_offset` and unchanged report parameters to pin Search Console rows. A changed publication returns HTTP 409 `publication_changed`; restart at offset zero without the old token. This does not pin live on-site metrics. `publication` is null when the report is not ready.
- `format=csv` on ranked HTTP routes returns the requested page as `text/csv`, including a header row even when empty. `X-SEO-Status` gives the report status. `X-SEO-Coverage-Partial` is `true` if either requested period is partial. Page and landing-page exports include `page_normalized`. With `compare=true`, it includes `previous_clicks`, `previous_impressions`, `previous_ctr`, and `previous_position`. Landing pages add `match`, `onsite_*`, and, for comparison, `previous_onsite_*` columns. Nulls are blank and formula-like text is escaped for spreadsheets. MCP and saved panels return JSON only.
- `/landing-pages`: `conversion_event` is an exact case-sensitive Mythic event name. Omit for null conversions.
- `/breakdown`: required `dimension=device` or `dimension=country`. Supports the same filters and pagination as other ranked reports.
- `/brand`: required `brand_terms` (e.g. `acme,acme tools`). Send 1–20 literal substrings, each up to 200 characters. Any match is branded, case-insensitively. The report echoes the normalized, deduplicated terms. Supports dates and comparison, not dimension filters, since the residual is computed from property totals.

```bash
curl -G 'https://mythic-analytics.gulp.workers.dev/client/v1/seo/overview' \
  -H "Authorization: Bearer $AK" \
  --data-urlencode "location_id=$LOCATION_ID" \
  --data-urlencode 'from=2026-11-01' --data-urlencode 'to=2026-11-07' \
  --data-urlencode 'compare=true'
```

### Response fields and availability

- `not_connected`: no active connection. `pipeline_disabled`: enable the client pipeline and enroll this connection. `copy_disabled`: enable Tinybird copy on the client pipeline. `syncing`: the required grain has not finished its first copy. All have `synced_at: null`. `ok`: an initial copy completed, even if it produced no rows. A failed refresh does not publish any rows or advance `synced_at`. An empty completed refresh replaces older rows in its window. Use [Airbyte](/airbyte-api/overview) for live job state. `/status` returns the oldest of the latest successful copy times across all grains. Reports use only their required grains. `/brand` uses both property and query grains and returns the older of their latest successful times.
- `coverage` is `{current, previous}`. Each period has `first_date`, `last_date`, `days_covered`, `days_requested`, and `partial`. Coverage counts distinct dates with published rows in the report grain, before dimension filters. Dates are null if there are no rows. The brand report’s `coverage` measures the property grain and `query_coverage` measures the visible query grain separately. `coverage.previous` is null unless comparing. A partial period can still return metrics for observed days. Do not compare it to a full period without displaying the coverage.
- `/overview`: `metrics` and `previous` are each `{clicks, impressions, ctr, position}` or null. A not-ready report returns null totals. The list and trend routes return `rows: []` when not ready.
- `/trend`: `rows` has `{date, metrics, previous}`. `metrics` is a metrics object or null. When present, `previous` contains `{date, clicks, impressions, ctr, position}` with the actual previous date. Days with no observation in either period are omitted.
- `/queries`, `/pages`, and `/breakdown`: each row has `query`, `page`, or `value` respectively, the four metrics, and `previous` (a metrics object or null). `/breakdown` echoes `dimension` at report level. `/landing-pages` adds `match`, `onsite`, and `onsite_previous` to each page row. Each on-site object has `sessions`, `conversions`, `lcp_p75_ms`, `inp_p75_ms`, and `cls_p75`. `onsite_previous` is null without comparison or if there was no match in that period. `conversion_event` is echoed at report level (null if unset).
- `/brand`: `branded`, `non_branded`, and `anonymized` each have `{metrics, previous}`, with metrics objects or null. All three groups use only dates published for both grains. `anonymized` means traffic not in visible queries (anonymized or truncated by Google). It subtracts visible query totals from property totals on comparable dates. CTR is computed from the difference and position is always null. If there are no comparable totals or either difference is negative, that period’s `anonymized` metrics are null.
- `previous_range` is null when not comparing. Missing observations are null, not a claim of zero activity. CTR is `clicks / impressions` (0–1). Position is weighted by impressions. Both are null with zero impressions.
- Unfiltered overview and trend use Google's daily property totals. A single dimension uses its aggregate stream. Query-free combinations use property-by-country/device or page-by-country/device streams. Only reports involving queries use query-bearing streams. Google hides anonymized queries and may cap returned rows, so filtered totals and row sums need not equal a property total. Results cover finalized Google web search only.

### How the landing-page join works

We match the full landing URL after removing the query string, fragment, and one trailing slash. Scheme, host, and path case must otherwise match. Both page routes return the original Search Console URL as `page` and the join key as `page_normalized`. URL variants keep separate search metrics. If variants share a normalized URL, they can repeat the same on-site metrics. Do not sum those values across variants. Redirect targets and aliases are not inferred. A page with no matching tracked landing session or Core Web Vitals observation in the current period returns `match: "none"` and `onsite: null`, not zero activity. A matched page returns `match: "matched"` and can legitimately have zero organic sessions.

Sessions are classified as **Organic Search** by Mythic's session channel rules, which exclude paid clicks. Conversions count distinct events by event UUID in those sessions, during the same reporting window. Missing visits or selected events count as zero. Core Web Vitals are p75 for all measured visits to that URL, not just organic visits. LCP and INP use milliseconds and CLS is unitless. A missing vital is null. Google filters select the Google rows and pages, but do not filter the on-site metrics for those pages. Search clicks and tracked sessions measure different populations and will not reconcile one to one.

## Dashboard panels

Save the reports as [analysis panels](/builder-api/insight-config#analysis-panels) to run them as the viewer. For example, use `insight_type: "line"` with `config.analysis: { "kind": "seo_trend", "params": { "days": 28, "compare": true } }`. The panel's `result` is the corresponding HTTP `data` object described above.
