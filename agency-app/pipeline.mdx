## Overview

The **Data pipeline** screen runs a client's ad platform connections, such as
Meta Ads and Google Ads, together once a day. If a sync fails, the run is
held until it is fixed. When every connection has synced, Mythic can tell
your system that the data is in. Open a client and choose **Data pipeline**.

## Connect a source

Click **Connect a source** to add an ad platform for this client.

1. Choose the **Platform**: Google Ads, Meta Ads, Bing Ads, TikTok Ads or
   Salesforce. A platform the client already has is marked **Already
   connected**. Each client can have one connection per platform.
2. Enter what the platform asks for. Meta asks for the ad account ID, with or
   without `act_`. Google asks for the 10-digit customer ID. Enter several,
   separated by commas, to sync them through one connection. Bing also asks
   for your developer token and tenant ID. TikTok asks for nothing.
3. Click **Continue to** the platform, sign in, and approve access. Use a
   login that can see the account. Mythic never sees the password or token.

You come back to this screen with a confirmation, or the reason it failed, such
as a login that can't reach the account. The first time you connect from the
agency app, Mythic adds the app's address to your agency's allowed return
pages.

A new connection joins the client's pipeline, and Mythic creates a daily
pipeline if the client has none. Its first sync copies past data and can take
a few hours.

## Manage a connection

**Connections** lists every connection the client has, whether the pipeline
runs it, and its last sync. The **⋯** menu on a row has:

- **Change tables**: choose what the connection syncs. The list is Mythic's
  default tables for the platform plus any the connection already syncs. A
  table you add copies its past data on the next sync. A table you remove
  stops updating but stays in BigQuery.
- **Rename**: the name shown here, in run details and in Airbyte.
- **Sync now**: syncs it straight away, outside the daily run.
- **Pause** and **Resume**: the pipeline skips a paused connection. Only
  connections in the pipeline can be paused.
- **Reconnect**: changes the account IDs or the login. Account IDs and the
  login can't be changed on an existing connection, so Reconnect deletes it
  and starts **Connect a source** with the old account IDs filled in. The
  tables stay in BigQuery, and the new connection copies the full history
  again.

Meta's default tables are campaigns, ads, daily results by action type and by
region, images, videos, ad creatives with their URL tags, and the account
change log. Connections created before the change log was added don't have
it until you add it with **Change tables**.

## Set up a pipeline

1. Click **Set up pipeline**.
2. Leave **Run every day** on, and choose the time in **Run at**.
3. Choose the connections to include. A connection that has never synced
   backfills on its first run and does not hold up the others.
4. Optionally enter a **Completion webhook** URL. Mythic sends it a POST once
   every connection in a run has synced. Add a **Signing secret** so your
   system can verify the request came from Mythic.
5. Click **Set up pipeline**.

Connections in a pipeline stop syncing on their own schedule and sync only as
part of the pipeline. Removing a connection from the pipeline gives it its
old schedule back. Turning **Run every day** off keeps the settings but stops
the daily run and gives every connection its schedule back.

**Edit** changes the settings. **Run now** starts a run straight away.

## Runs

The screen lists recent runs with the day, status, connections synced,
records, how long it took, and whether it was started by the schedule or by
hand.

| Status | Meaning |
| --- | --- |
| **Running** | Syncs are in progress. |
| **Held** | At least one sync failed after its retries. The run keeps retrying every five minutes and completes on its own once the sync passes. |
| **Complete** | Every connection that could sync did, and the webhook was sent. |
| **Failed** | The run made no progress for 36 hours. |
| **Superseded** | A manual run replaced it. |

A connection that is turned off or not due that day is **Skipped** and does
not hold the run.

## Fix a held run

Click a run to see each connection, its status, records and last success,
and the reason the run is held. Fix the cause, such as an expired login to
the ad account, then:

- **Retry failed**: syncs the failed connections again on the next check,
  within 5 minutes.
- **Complete anyway**: marks the run complete and sends the webhook now
  without the missing data. The run and the webhook are marked **Forced**
  permanently, because anything built on them used incomplete data.
- **Resend webhook**: sends the completion webhook again for a finished run.
