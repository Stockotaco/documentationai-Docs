## Before you start

- The client's plan includes MCP analytics (it comes with Logs) and the location is not in HIPAA mode.
- The location's **publishable key** (`pk_…`). The agency app shows it on the client's **MCP analytics → Setup** tab, and `GET /client/v1/mcp-analytics/setup` returns it as `publishable_key`.
- A Node.js MCP server built on `@modelcontextprotocol/server` 2.x or `@modelcontextprotocol/sdk` 1.22.0 to 1.32.2, on Node.js 18 or later. A server with its own JSON-RPC dispatcher uses [`MythicMCP`](/mcp-analytics/typescript#servers-without-an-sdk-server-object) instead.

<Callout kind="info">
The publishable key identifies the location. It is the same `pk_` key the browser snippet uses and is not a secret.
</Callout>

## Install

```bash
npm install @mythic-analytics/mcp
```

The package has no runtime dependencies. `@modelcontextprotocol/sdk` releases below 1.22.0 are not verified.

## Instrument the server

<Steps>
  <Step title="Call instrument after creating the server">

```ts
import { McpServer } from '@modelcontextprotocol/server';
import { instrument } from '@mythic-analytics/mcp';

const server = new McpServer({ name: 'acme-crm', version: '1.4.0' });

const analytics = instrument(server, {
  apiKey: process.env.MYTHIC_PUBLISHABLE_KEY, // pk_…
});

server.registerTool('search_contacts', { /* … */ }, async (args) => { /* … */ });
```

Tools registered before or after `instrument` are both observed. Calling `instrument` twice on the same server returns the first handle, so nothing is counted twice.

  </Step>
  <Step title="Flush before the process exits">

```ts
process.once('SIGTERM', async () => {
  await analytics.shutdown(2000);
  process.exit(0);
});
```

Events are queued in memory and sent every 5 seconds or every 20 events. On a serverless runtime, create the client yourself with `waitUntil` so the send outlives the response:

```ts
import { createMythicClient, instrument } from '@mythic-analytics/mcp';

const client = createMythicClient({
  apiKey: env.MYTHIC_PUBLISHABLE_KEY,
  waitUntil: (p) => ctx.waitUntil(p),
});
const analytics = instrument(server, { client });
```

  </Step>
  <Step title="Add the session middleware (Streamable HTTP only)">

`instrument` cannot set HTTP headers. On a Streamable HTTP server, add the middleware from `@mythic-analytics/mcp/http` so a client's calls stay in one session across requests:

```ts
import { mythicSessionNode } from '@mythic-analytics/mcp/http';

app.use('/mcp', express.json(), mythicSessionNode({ sessionSecret: process.env.MYTHIC_SESSION_SECRET }));
```

Mount it after a JSON body parser so it can see `initialize`. Skip this for stdio servers. See [Conversation ID and sessions](/mcp-analytics/conversation-id).

  </Step>
  <Step title="Check that events arrive">

Call one tool from any MCP client, then open the client's **MCP analytics → Setup** tab, or:

```bash
curl "https://mythic-analytics.gulp.workers.dev/client/v1/mcp-analytics/setup?location_id=loc_123" \
  -H "Authorization: Bearer $MYTHIC_AGENCY_KEY"
```

`last_event_at`, `events_24h` and `servers` show what Mythic received.

  </Step>
</Steps>

## What changes for agents

With the defaults, two things become visible in `tools/list`:

- Every tool gains an optional `context` string argument, where the agent says why it is calling. It costs about 25 tokens per tool. The SDK removes it before your handler runs. Turn it off with `context: false`. See [Intent](/mcp-analytics/intent).
- A `get_more_tools` tool, where an agent reports a capability it could not find. Turn it off with `reportMissing: false`. See [Missing capabilities](/mcp-analytics/missing-capability).

Nothing else changes: tool results, errors and schemas reach the client exactly as before.

To record volume, errors, latency, sessions and clients only, with no arguments, responses, intents or added tools:

```ts
instrument(server, { apiKey: process.env.MYTHIC_PUBLISHABLE_KEY, metadataOnly: true });
```

## When ingestion refuses events

| Status | `code` | What the SDK does |
| --- | --- | --- |
| 401, 403 | Invalid key, `not_entitled`, `hipaa_restricted` | Pauses sending for 10 minutes. Events captured while paused are dropped |
| 429 | `rate_limited` | Retries twice, honoring `Retry-After` up to 30 seconds, then drops the batch |
| 429 | `quota_exceeded` | Pauses for `Retry-After`, at most 15 minutes |
| 5xx, network failure | `mcp_unavailable`, `privacy_unknown`, `entitlements_unavailable` on 503 | Retries twice, honoring `Retry-After` up to 30 seconds, then drops the batch |

`client.stats()` on a [client you created](/mcp-analytics/typescript#the-client) reports sent, dropped and rejected counts. See [Events](/mcp-analytics/events#ingestion) for the full contract.
