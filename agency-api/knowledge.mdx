  Knowledge is an invite-only private beta. It is not included in any plan, including unrestricted plans.
</Callout>

Knowledge stores agency-owned text in **collections**, each made up of **documents**. A handbook can be a collection and each chapter a document. Mythic splits uploaded text into overlapping chunks and indexes them for retrieval.

## Base URL and authentication

```text
https://mythic-analytics.gulp.workers.dev/client/v1/knowledge
```

Send `Authorization: Bearer <key>` from a server. Use an agency key (`ak_`) or an agency-wide MCP key (`mcp_`). Search, chat, and list require `knowledge:read`; create, upsert, and delete require `knowledge:write`, which also grants read. Client-bound keys are not accepted. The per-agency API limit is 120 requests per minute, in addition to per-key limits. There is no browser CORS support.

## Collections and documents

| Method and path relative to the base URL | What it does |
| --- | --- |
| `GET /collections` | List collections ordered by position and slug |
| `POST /collections` | Create a collection with a pinned embedding provider |
| `DELETE /collections/{collectionId}` | Permanently delete the collection, documents, and chunks |
| `GET /collections/{collectionId}/documents` | List document metadata ordered by position and slug |
| `POST /collections/{collectionId}/documents` | Create or replace a document by its slug |
| `DELETE /collections/{collectionId}/documents/{documentId}` | Permanently delete one document and all its chunks |
| `POST /search` | Return ranked lesson passages with the matching chunks identified |
| `POST /chat` | Answer a question with citations within a scope |

List responses return `data.items` and `data.next_offset`. Use `?limit=100&offset=0` to start. `next_offset: null` marks the final page. IDs outside the agency or requested collection return `404 not_found`.

Create a collection with `title` and a unique lowercase hyphenated `slug`. Optional fields are `description`, `position` (default 0), and `embed_provider`. Omit the provider to use the agency's default model-key provider. Creation returns `201` with collection metadata, including `embed_provider`, `embed_model`, and `embed_dims`. A duplicate slug returns `409 collection_slug_exists`.

Upsert a document with `title`, `slug`, and plain `text`. Optional fields are `module`, `position` (default 0), and `source_ref`, for example the source URL. The slug is unique within the collection. The API accepts up to 180,000 text characters and 100 chunks per document. Audio-marker-only lines such as `[BLANK_AUDIO]` are removed before indexing.

The response is `data: { document, changed }`. Identical cleaned text is a no-op. It returns `changed: false` without changing the metadata, chunk IDs, or embeddings, even if the new request supplies different metadata. Changed text entirely replaces the chunks in one transaction. If embedding or storage fails, the prior version stays visible. Document lists return metadata, not the indexed text.

## Search and chat scope

| `scope` | Pass |
| --- | --- |
| `all` (default) | No IDs |
| `collection` | `collection_id` |
| `document` | `document_id`, optionally `collection_id` to check its parent |

Search accepts `query`, `mode`, and optional `k` (default 8, range 1 to 20). Use the same `query`, `k`, and scope to compare retrieval modes:

| `mode` | Ranking |
| --- | --- |
| `hybrid` (default) | Blends keyword and vector ranks using reciprocal rank fusion with a constant of 60. Promotes one passage per matching lesson using title and module terms |
| `vector` | Exact cosine ranking within each embedding space. Cosine scores across providers are not calibrated |
| `keyword` | English full-text search. Titles and modules carry more weight than body text. No embedding key or call required for search |

In keyword or hybrid mode, double quotes request a phrase, `OR` accepts alternatives, and a leading `-` excludes a term. Plain queries prioritize full matches and can fall back to partial matches. Hybrid and vector send one query per embedding space. Empty scopes return an empty array without calling a model.

`k` limits ranked hits **before** context expansion. `data` is an array ordered by each passage's best match. Each passage contains the collection and document IDs and titles, `module`, expanded `content`, and `token_estimate`. `chunks` lists contributing `chunk_id` and `ordinal` pairs in document order. `matches` lists only the original ranked hits, with `chunk_id`, `ordinal`, `score`, `keyword_rank`, `keyword_score`, `vector_rank`, `similarity` (cosine), and `title_boost`. `score` includes `title_boost`, which is zero in keyword and vector mode. Rarer label matches count more, and a title match counts more than a module match. Rank and similarity fields for legs that did not contribute are `null`. Neighboring chunks add context, overlapping windows are merged, and the response is capped at 20,000 estimated text tokens. The result can contain fewer passages than `k`.

Chat accepts the same scope and retrieval `mode`, and 1 to 12 `messages` with `role` (`user` or `assistant`) and `content` (up to 4,000 characters per message), ending with a user message. The last message drives retrieval, so make follow-up questions self-contained. The model receives conversation history and expanded passages grouped by lesson, labeled with course and module, capped at 7,500 estimated source tokens. A response has `data.answer` and `data.citations`. Each citation contains `document_title`, `collection_title`, `chunk_id`, and a short `excerpt` copied from the cited chunk, which can be a neighbor. If the model attempts an answer with invalid citations, chat retries once using the same sources and stricter citation instructions. If retrieval is weak or the answer still cannot be backed by verified excerpts, the answer is `Not in the material.` with an empty citations array. Chat does not store history or stream responses.

## Your model keys

Set an agency-wide key with `PUT /client/v1/replay-vision/keys` before creating collections or using models. Client-level key overrides are not used. A collection pins one model and dimension for its lifetime:

| Provider | Embedding model | Dimensions |
| --- | --- | ---: |
| `openrouter` | `openai/text-embedding-3-small` | 1536 |
| `gemini` | `gemini-embedding-001` | 768 |
| `cloudflare` | `@cf/baai/bge-m3` | 1024 |

Chat uses the agency's default key and the same model defaults as [Scouts](/agency-api/scouts). Pass `model` to choose a compatible model on one of the agency's stored providers. Cloudflare chat supports Workers AI `@cf/` models, not Gemini models through AI Gateway. A missing or unreadable required key returns `409`; there is no Mythic-funded fallback.

Uploaded text and queries using hybrid or vector go to the embedding provider. In chat, supplied messages and relevant passages go to the chat provider, which can differ from the embedding provider. Keyword chat skips the embedding call but still needs a chat key. Your provider's retention and usage charges apply. Only upload material you have permission to send to those providers.
